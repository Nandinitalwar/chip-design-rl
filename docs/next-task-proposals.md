## 1. Per-channel credit accounting with same-cycle return

**Proposed ID:** `rtl-vc-credit`. **Suggested first assignment.**

**Engineering setting and scope.** A fabric transmit scheduler shares a downstream link across virtual channels. Repair the credit manager that accepts one send request and independently receives one returned credit per cycle. A boundary bug stalls a usable channel or lets one channel spend another's capacity. Supply an original compiling manager with a localized accounting defect, an immutable scheduler-facing wrapper, and a short transaction trace. The candidate edits the manager only; arbitration and physical link timing are outside scope.

**Proposed cycle contract.** Parameters `CHANNELS` in 1..5 and `DEPTH` in 1..4; all channels have that credit capacity. Port ID widths are at least one bit. Each channel starts at DEPTH available credits after an active-high synchronous reset edge. Reset suppresses send-ready combinationally and ignores returns at that edge.

A send occurs when `send_valid && send_ready` at the edge, debiting `send_channel`. A valid return credits `return_channel` at that edge. For a legal selected send channel, ready is true exactly when its old count is positive **or** a return for that same channel is present in the current cycle. This permits zero-credit return-and-send with no bubble. Different-channel events update independently. An out-of-range send ID yields ready zero; an out-of-range return ID is ignored. Legal return traffic obeys `old_count + return - accepted_send <= DEPTH`; overflow behavior is outside the contract, not a hidden test. Returned credits are fungible within a channel. Ready may depend on the selected channel even when send-valid is low; the test must check the disclosed equation in that case too.

**Failure hypotheses.** Primary `RTL-ORDER`: separate assignments lose either the return or debit on a same-channel collision. Secondary `RTL-LIVE`: requiring a positive old count inserts a bubble at zero despite a matching return; `RTL-ALIAS`: returns replenish the wrong channel; `RTL-PARAM`/`RTL-WIDTH`: counter width cannot represent DEPTH or non-power-of-two IDs wrap incorrectly. None is an observed Astra failure.

**Deterministic grading.** Use an integer conservation ledger per channel rather than RTL-style next-state branches: initial credits plus returns minus accepted sends. Compare exact ready before every edge and update the ledger only after checking acceptance. Exhaustively explore reachable count vectors and legal event choices for CHANNELS=1/2, DEPTH=1/2; use explicit deterministic boundary walks and fixed-seed traffic for all 20 declared parameter combinations. Exercise every channel at zero and capacity, same/different-channel collisions, reset with activity, invalid IDs when encodable, and independent-channel progress. No fairness property is imposed on the external scheduler.

**Required negative controls.** Reject implementations that omit zero-count return forwarding, drop the return on a simultaneous send, credit the send channel instead of the return channel, under-size the count, or mask channel IDs to two bits. Each mutant must have a named directed witness, in addition to mixed traffic. Oracle confidence requires independently derived credit-conservation assertions and the ledger scoreboard.

**Difficulty adjustment before a future freeze.** Start with the manager repair. If independent screening is too easy, propose a new version integrating two send lanes with an explicitly ordered admission rule; do not silently add multi-lane tests to this contract.

## 2. Tagged response reorder queue with cancellation

**Proposed ID:** `rtl-tagged-retire`.

**Engineering setting and scope.** A small accelerator issues commands in order, receives completions out of order, and retires results in issue order. Repair the allocation/completion/retirement controller. Provide an immutable completion adapter and retirement sink wrapper so traces expose the system consequence of incorrect slot reuse. This is a bounded reorder queue, not a full CPU reorder buffer or standard bus implementation.

**Proposed cycle contract.** Parameters `SLOTS` in 1..5 and `WIDTH` in {1, 9, 17, 32, 65}; slot IDs have width `max(1, ceil(log2(SLOTS)))`. Allocation reserves the next circular slot and exposes its ID as `alloc_tag`, meaningful when allocation-ready is high. Occupancy includes incomplete and completed entries. Completions carry tag and WIDTH-bit payload. Only a completed oldest entry may assert retirement-valid. Retirement payload and tag remain stable under backpressure unless reset or flush is asserted.

Combinational allocation-ready is true exactly when occupancy is below SLOTS or an already-valid retirement will transfer that edge. Empty queues do not bypass allocation or completion to retirement. Completions update only entries allocated before that edge; upstream guarantees each such entry completes at most once and not before the cycle after allocation. Therefore a completion cannot target an already completed retiring entry or a newly allocated slot, including same-edge slot reuse. Completion effects become visible after the edge. Concurrent retirement removes the old head and allocation appends a fresh incomplete entry, even when both use the same physical slot at full capacity.

Reset and flush suppress allocation-ready and retirement-valid combinationally and clear all occupancy at the edge, overriding allocation, completion, and retirement. **The upstream cancellation contract guarantees that no pre-flush completion arrives after the flush edge.** Completions coincident with flush are ignored. Generation tags and stale-response detection are intentionally outside this task; a future version supporting stale responses would need a new interface and wraparound contract. Completion traffic with an invalid, free, or duplicate tag is otherwise outside the legal input domain.

**Failure hypotheses.** Primary `RTL-STATE`: a reused slot retains its old completed bit or payload and retires an uncompleted command. Secondary `RTL-ORDER`: completion and retirement collide incorrectly; `RTL-HANDSHAKE`: a later completion changes the stalled head; `RTL-RESET`: canceled results remain visible; `RTL-PARAM`: full/empty or pointer wrap breaks at SLOTS=1 or non-power-of-two capacities.

**Deterministic grading.** Maintain an ordered software-style list of allocated records and a tag-to-record map; mark records complete from input events, then compare the oldest record against retirement outputs. Keep list ordering independent of the DUT's circular-index equations. Verify exact allocation-ready and allocation tag against the specified allocation sequence. Assert uniqueness of live tags, one retirement per accepted allocation, payload identity, and no retirement before completion. Drive reverse-order completions, head-of-line blocking, full retirement-plus-allocation, multiple wraps, arbitrary retirement stalls, and flush/reset at each occupancy. Explicitly complete each reused slot with a different full-width payload. Cover all 25 parameter combinations; use bit-walking and fixed-seed full-width data, not a narrow random slice. Exhaustively enumerate short legal traces for SLOTS=1/2 and use longer deterministic traces for the rest.

**Required negative controls.** Reject stale completed-bit reuse, retirement in completion order, completion-to-retirement combinational bypass, rejection of full same-edge replacement, modulo-by-power-of-two wrap, ignored flush, and payload truncation above bit 16. Each gets an explicit trace. Separately assert allocation/retirement conservation across cancellation epochs to reduce correlated oracle/scoreboard error.

**Difficulty adjustment before a future freeze.** The initial integration includes one completion port. Multiple completions or cancellation generations are separate future contracts, never undisclosed grader requirements.

## 3. Dual-port byte-write merging and registered read forwarding

**Proposed ID:** `rtl-byte-forward`.

**Engineering setting and scope.** Two control paths update byte fields of a small accelerator configuration bank while a pipeline samples one register per cycle. A simple port-priority mux drops non-overlapping writes, and an incomplete bypass mux returns stale bytes. Repair the bank's merge/forward logic inside a supplied register-access wrapper. This exercises a realistic datapath/control interaction distinct from queue and arbitration state machines.

**Proposed cycle contract.** Parameters `WORDS` in 1..5 and `BYTES` in {1, 2, 3, 4, 9}; data width is exactly `8*BYTES`, with one write strobe per byte and address widths at least one bit. Both write ports accept their enabled, strobed bytes at every rising edge. If both target the same word, disjoint byte writes merge and port 1 wins **only overlapping enabled bytes**. A zero strobe changes nothing. Invalid write addresses are ignored; invalid read addresses produce zero data with a valid read response.

A read request is sampled on an edge; immediately after that edge, response-valid equals the sampled request-valid. For a valid request, the registered response is the addressed word **after merging writes from that same edge**, including partial writes and both ports. It remains unchanged until the next valid read request or reset. There is no response backpressure. Without a request, response-valid goes low and response-data holds its previous value. Active-high synchronous reset clears storage, response-valid, and response-data at the edge and ignores simultaneous requests/writes; there is no asynchronous output gating requirement. The bounded bank may synthesize as flip-flops; SRAM inference, PPA targets, and power-on state before reset are outside scope.

**Failure hypotheses.** Primary `RTL-WIDTH`: word-wide priority or sign/width mistakes corrupt byte lanes. Secondary `RTL-ORDER`: forwarding sees pre-write data or one port only; `RTL-ALIAS`: unequal addresses incorrectly merge; `RTL-PARAM`: default-only lane loops miss byte 8 or non-power-of-two address handling; `RTL-RESET`: reset loses priority over a write.

**Deterministic grading.** Model memory as an array of individual bytes. Apply enabled port-0 bytes, then enabled port-1 bytes, then form the sampled read response. This independent byte-level model avoids duplicating the oracle's word-mask expressions. Compare response-valid every cycle, valid response data after each edge, and required held data on idle cycles. Sweep every word and lane, same/different-address writes, each pair of one-hot strobes, zero/all strobes, read/write collisions, invalid encodings when available, and reset during collisions. Test all 25 parameter combinations. Enumerate all strobe pairs for BYTES<=4; for BYTES=9 use directed overlapping/disjoint/upper-lane patterns plus deterministic full-width random traffic. Verify every lane can change independently; finite simulations are not an all-traces proof.

**Required negative controls.** Reject whole-word port-1 priority, reversed overlapping-byte priority, old-data reads, forwarding from only port 0, zero-strobe forwarding, loops fixed at four bytes, and address truncation to two bits. Confirm legal implementations using different merge organizations pass the same tests.

**Difficulty adjustment before a future freeze.** Begin with simultaneous merge and registered read repair. Additional pipeline stages or response backpressure require a separately specified version; avoid increasing difficulty with unstated timing conventions.
