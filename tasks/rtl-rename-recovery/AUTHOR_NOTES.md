## Implementation organization and independent checking

`design.sv` maintains an ordered bounded array of retirement records and event transitions. `map_bypass.sv` reconstructs the speculative map and intra-bundle sources. `ownership.sv` derives owned/readiness masks and chooses free tags. The starter contains interacting defects in pending ownership, same-bundle bypass and physical-only completion matching. It compiles and has a small public smoke test; passing that smoke does not establish the full contract.

The oracle reconstructs state using packed arrays and bounded RTL loops. The external Python reference instead maintains an instruction-history ledger with individually owned objects, committed mappings and transport reservations. It checks candidate allocations against an allowed set and updates its own mapping from the chosen legal tag. It does not compare an allocator's chosen priority or checkpoint bitmask to oracle internals. A descending-priority positive control demonstrates allocation freedom alongside the ascending oracle. A third positive control sets only invalid destination output lanes to X; binary serialization preserves adjacent defined bits exactly.

The ledger checks exact maximal-prefix admission, source/stale/readiness fields, full retirement records, committed stale-tag consistency, unique live destinations, committed/live disjointness, and accepted = retired + killed + reset-discarded + live conservation. It retains completion transport objects after kills until response consumption. Model input-generation assertions are infrastructure/verifier defects, distinct from explicit candidate mismatch exceptions.

Directed schedules include both branch lane boundaries; both completion/resolution orders; completion on a recovery edge; two older commits on rollback; same-destination bypass; port-1-only completion and both dual-port permutations; retirement valid=11/ready=01 compaction; no-destination/zero metadata; checkpoint saturation and selective reuse; physical/ROB capacity and pre-edge freeing; downstream stalls; reset during all event types; numeric token wrap; repeated older commits after checkpoints; and late killed responses after allocator-independent physical reuse. More than twice the physical-register count of kill/reallocate rounds forces some tag reuse by any legal allocator, without forcing a particular tag. The 48 reduced scenarios exhaust the declared product of branch lane, completion order, correct/recovery resolution, retirement ready prefix and destination choice; they are not exhaustive state-space or formal proofs. Each of six configurations also runs 1,400 fixed-seed stress cycles, followed by transport/retirement drain.

Semantic controls include missing bypass, inclusive branch kill, lost same-edge commit, physical-only completion, premature pending-register release, one-lane dispatch, missing correct-resolution release, unresolved-branch retirement, wrong zero-destination metadata, snapshot free-list leak, numeric-token age, and incorrectly gating completion port 1 on port 0. The snapshot control isolates registers that were owned at checkpoint creation and become free before rollback, retaining those bits in a blocked mask to reproduce resource leakage without introducing unsafe allocations. There are thirteen negative controls including the compiling starter, plus three positive implementations. Negative controls must synthesize and fail a directed functional witness; synthesis errors cannot count as semantic discrimination.
